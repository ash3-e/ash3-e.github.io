Lab 12: Arduino II (Debouncing, Interrupts, Libraries, Serial Communication)
Overview
Second Arduino lab covering software debouncing of mechanical pushbuttons (a closed switch's contacts vibrate over a few ms producing a random number of HIGH/LOW pulses, leaving the LED toggle in an unpredictable state — fixed by adding a small post-edge delay() to mask the bounce), hardware interrupts via attachInterrupt(0, ISR, mode) on digital pins 2 and 3 of the UNO with modes LOW / CHANGE / RISING / FALLING, the difference between polling (loop checks the pin) and interrupt-driven (CPU is free until the pin changes), installation and use of an external library (TimerOne) for precisely-timed periodic interrupts, parallel vs. serial communication (parallel uses one wire per bit and is fast but wire-heavy; serial uses a single line and is slower but cheap), and the I²C and SPI low-level serial protocols, demonstrated with a 16×2 LCD wired first in parallel and then with a serial backpack. This transcript is a page-specific reconstruction for preview and search.

Problem coverage
The set is centered on robust digital input and on serial vs. parallel communication. The pages clearly include the button-LED toggle sketch where buttonState transitions LOW → HIGH flip ledState, the failure rate of about 50 % without debouncing because of the contact bounce, the cure with delay(200) (or with a software flag tracking the time since the last edge), the bouncing waveform on the oscilloscope (zoom horizontal axis, normal trigger mode), the comparison sketch for polling versus interrupt where the polling sketch wastes the CPU in a 100×delay(10) loop and misses fast button presses while the interrupt sketch responds immediately, the syntax attachInterrupt(0, bEvent, CHANGE) tying the ISR bEvent() to digital pin 2 and the volatile keyword required on any global variable accessed inside the ISR, the four supported triggering modes LOW, CHANGE, RISING, FALLING, the explanation that delay()/millis() rely on interrupts and so won't work inside an ISR (use delayMicroseconds), the Arduino library system (Sketch > Include Library > Add .ZIP Library) and the TimerOne library that lets a periodic ISR be attached every 500 000 µs = 0.5 s independent of what the loop is doing, the parallel-vs-serial intro (8 wires for one byte vs 1 wire serially), the I²C ("I two C") and SPI low-level serial protocols, the 16×2 LCD wired first as a parallel interface (lots of wires, easy to make wiring mistakes) and then again with the LiquidCrystal_I2C library on a 4-wire I²C backpack.

Key equations

$$\text{Button state: }\text{buttonState}=\text{digitalRead(buttonPin)}$$

$$\text{Edge detection: }\text{toggle iff buttonState}=\text{HIGH AND lastButtonState}=\text{LOW}$$

$$\text{Bounce duration: }\Delta t_{bounce}\sim 1\text{–}10\ \text{ms}$$

$$\text{Software debounce delay: }t_{db}\gtrsim \Delta t_{bounce}\quad\text{(typically 50–200 ms by hand)}$$

$$\text{Polling latency: }t_{lat}^{poll}=t_{loop}\quad\text{(time around the main loop)}$$

$$\text{Interrupt latency: }t_{lat}^{ISR}\sim 4\text{–}16\ \text{clock cycles}\approx \frac{4\!-\!16}{16\ \text{MHz}}\sim 1\ \mu\text{s}$$

$$\text{ISR syntax: }\text{attachInterrupt}(\text{interruptNumber, ISR, mode})$$

$$\text{UNO has 2 hardware interrupts: 0 on Digital Pin 2, 1 on Digital Pin 3}$$

$$\text{Trigger modes: LOW, CHANGE, RISING, FALLING}$$

$$\text{Volatile globals required to share data between ISR and loop()}$$

$$\text{TimerOne period: }T_{ISR}\ \text{set by Timer1.initialize}(T_{\mu s})$$

$$\text{Example: Timer1.initialize}(500{,}000)\Rightarrow T_{ISR}=0.5\ \text{s}$$

$$\text{Parallel: }N_{wires}=N_{bits}+\text{ground}+\text{clock}$$

$$\text{Serial: }N_{wires}\sim 2\text{–}4\quad\text{(SDA/SCL or MOSI/MISO/SCK/SS)}$$

$$\text{Bit time: }T_{bit}=\frac{1}{f_{clock}}\quad\text{(one bit per clock period in synchronous serial)}$$

$$\text{Baud rate (asynchronous): }B=\frac{1}{T_{bit}}\quad\text{(bits per second)}$$

$$\text{Time to transmit 8-bit byte (parallel): }T_{byte}=T_{clock}$$

$$\text{Time to transmit 8-bit byte (serial): }T_{byte}=8T_{bit}=\frac{8}{B}$$

$$\text{ASCII 'A' = 65 = 01000001}_{2}\Rightarrow 8\ \text{bits}$$

$$\text{I}^{2}\text{C: 2 wires (SDA, SCL), open-drain, multiple devices via 7-bit address}$$

$$\text{SPI: 4 wires (MOSI, MISO, SCK, SS), full-duplex master/slave}$$

How to use this page
Read each displayed relation as solving one of four jobs: deciding whether to use polling or an interrupt based on how time-critical the input is, masking switch bounce with a software delay or a debouncing edge counter, attaching an ISR to the right pin with the right mode and remembering to mark its globals volatile, or estimating how long it takes to send N bits in parallel versus serially given a clock or baud rate. That is the logic tying the handwritten algebra together.
